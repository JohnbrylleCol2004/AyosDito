# AyosDito PWA Implementation Plan

**Goal:** Make the existing HTTPS website installable on Android and Windows, with bilingual installation guidance and a safe offline fallback.

**Architecture:** Next.js App Router manifest, generated PNG icons from the existing green map-pin brand, a root client provider for browser install events and production service-worker registration, a public `/install` page, and a small service worker caching only a self-contained public offline document. Preserve all existing auth, evidence and report flows.

**Tech stack:** Existing Next.js/React/TypeScript, Sharp for brand icon exports, native service worker/manifest/browser installation APIs, Node and Playwright tests. No new package dependency.

**Design basis:** The user approved the previously described website-to-PWA approach and asked to implement it. Reuse existing branding and English/Filipino presentation. Android/desktop install controls are browser-dependent; manual guidance remains available. Internet remains required for authentication, reports, photos and notifications. This does not create an APK, EXE or store listing.

## Constraints and review focus

- Never cache authenticated documents, API/Server Action responses, Supabase requests or private evidence.
- Cache only `/offline.html`; no offline queue, background writes, user data or automatic page reload on worker update.
- Worker enabled in production on secure contexts; development remains unaffected.
- Handle absent/dismissed/rejected install prompts and standalone display honestly.
- Exclude public PWA assets from session refresh; use a no-cache worker script and no shared app-page caches.
- Existing uncommitted forwarding configuration and test belong to earlier work and must be preserved.
- Do not claim Vercel deployment or actual OS installation until independently verified; local implementation can be built and tested first.
