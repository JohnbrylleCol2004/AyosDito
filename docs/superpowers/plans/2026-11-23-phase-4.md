## Decisions and constraints

- Reuse private `report-photos` bucket. Authenticated users have no raw object write permissions; validated server code alone uploads using `SUPABASE_SECRET_KEY` in a server-only module. Other report operations still use user JWT/RLS.
- JPEG/PNG/WebP, 5 MiB each, at most 3 files per request, at most 3 resident photos per report. Decode actual content with pixel limits; re-encode to WebP without EXIF/location metadata. Admin resolution evidence is distinct and cannot be altered by residents.
- Reservation RPC locks report and enforces identity/status/slot count. Finalization and cancellation are trusted server-only RPCs. Pending/cancelled objects never receive viewing URLs. Cleanup handles interrupted uploads.
- Database generates storage paths and per-actor request-key uniqueness prevents duplicate upload reservations on retries. Signed viewing URLs expire after 120 seconds and are issued only after authorized ready-metadata reads.
- Publication is explicit, admin-only and separate from status acceptance. Moderators enter public title, summary and coarse zone; private title/description/location are not auto-published. Only published in-progress/resolved issues appear in anonymous-safe projections.
- Community confirmation uses auth.uid(), unique report/user constraint and explicit requested boolean, not a race-prone toggle. No confirming identities are projected.
- Notifications are generated by an audit-insert trigger in the same transaction; unique event/recipient prevents duplication. Only recipient reads/mark-read operations are allowed. No external messages or realtime subscription.
- Community/list/search and galleries are paginated. Analytics use bounded grouped data, monthly buckets and actual resolved timestamps; missing averages display an explicit empty value.
- Preserve current enum names and all existing private report RLS. No Phase 5/deployment work.
- Existing authorization to implement detailed briefs with reasonable defaults persists.
