# AyosDito Phase 2 Implementation Plan

> For agentic workers: use superpowers:executing-plans inline; request an independent final review.

**Goal:** Deliver resident issue reporting and tracking from the user-supplied Phase 2 brief.

**Architecture:** Extend existing Next.js server authorization, Supabase SSR clients, RLS, dictionaries and emerald application shell. A resident-only security-definer RPC owns report creation with a per-resident submission UUID for retry safety. Server Components perform bounded, owner-filtered reads; RLS also governs every query.

**Tech Stack:** Existing Next.js 16.4.6, React 19.3.1, TypeScript, Tailwind, Supabase and PGlite. No additional runtime dependency.

**Spec:** User attachment `617449fd-c053-464e-af0c-7271208d83df/Pasted text.txt`, Phase 2 Resident Issue Reporting & Tracking, supplied 2026-11-23.

## Constraints and decisions

- Implement Phase 2 only; no photo uploads or administrator mutations.
- Preserve Phase 1 enum values `pending_review` and `public_facility`; translate labels to the requested wording. The brief's `pending` and `facilities` examples map to these existing values.
- Preserve existing rows and migrations. Add one additive migration. Tighter checks apply to new writes without invalidating old rows at migration time.
- Title 5–120, description 20–2,000, zone 1–80, location at most 200 characters after trimming. Count Unicode code points consistently with PostgreSQL.
- New reports always belong to `auth.uid()`, start Pending Review and receive database timestamps/sequence numbers.
- Retries with the same submission UUID return the original report without updating it; a different payload using that UUID is rejected.
- Twelve reports per page, bounded search input, stable chronological ordering with ID tie-breaker. Literal search uses a security-invoker RPC with parameterized `strpos`, preserving punctuation without exposing filter syntax.
- Keep existing authentication, bilingual switching, admin dashboard and private report-read policies.
- User previously authorized direct implementation with reasonable defaults; current Phase 2 brief explicitly authorizes the next phase. No further design approval gate.

## Review focus

- Another resident's UUID and forged system fields must not reveal or change private records.
- Direct RPC calls must validate everything and reject anonymous/admin callers.
- Double clicks and request retries must not create multiple records.
- Missing migration, failed queries, empty results and nonexistent IDs need distinct safe handling.
- Filters, Unicode lengths, pagination, translated messages and real dashboard counts must agree.

Preserve form values, accessible client/server errors and loading state. Use current Next.js async params/searchParams conventions.
4. **Verification and handoff** — database/API security tests, browser route/workflow/responsiveness checks, independent review, lint/type-check/build, README migration instructions and honest hosted verification status.
