# AyosDito Phase 3 Implementation Plan

> For agentic workers: use superpowers:executing-plans inline and request independent final review.

**Goal:** Implement the supplied Phase 3 admin management and resolution tracking brief.

**Architecture:** Extend existing auth/RLS, typed dictionaries, app shell, report details and timeline. Admin-only database RPC locks a report, verifies its actual status and optimistic version, updates it and inserts one audit record in the same transaction. Server actions authorize independently; no service key is used by the app.

**Tech Stack:** Existing Next.js 16.4.6, React, TypeScript, Supabase, Tailwind, PGlite and Playwright. No new dependencies.

**Spec:** User attachment `eda959ff-9946-4900-81c7-efb7445f9b0f/Pasted text.txt`, supplied 2026-11-23.

## Constraints and decisions

- Preserve Phase 1–2 and existing migrations/data. Add Phase 3 migration only.
- Preserve actual enum `pending_review` (brief says `pending`, but requires existing schema compatibility).
- Allowed edges: pending_review→in_progress, pending_review→rejected, in_progress→resolved. Terminal states have no outgoing edges.
- Every transition requires a trimmed 1–2,000 character official note; Unicode code point counts and SQL trimming match existing Phase 2 validation.
- Database derives `admin_id` and old status. Client supplies only target status, note, report ID and an untrusted expected version used solely to reject stale writes.
- `SELECT FOR UPDATE` plus `status_version` prevents conflicting requests from chaining into unintended transitions. Failed/replayed stale requests create no audit entry.
- Existing timestamp trigger uses database clock; RPC reads its resulting timestamp and uses exactly that timestamp for the audit row.
- App administrators retain no direct table mutation grants. Existing RLS stays intact.
- Admin search is literal and parameterized; reporter name/profile zone are loaded only after server admin authorization and remain protected by RLS.
- Admin list: 12/page, exact zone filter, newest/oldest/pending-first sorts. Dashboard counts/category distributions are grouped from one database snapshot.
- No uploads, reopening, assignments or Phase 4 work.
- Existing user authorization to implement detailed briefs with reasonable defaults persists; execute directly.
